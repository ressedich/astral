# Сборка и раздача Astral для Windows

Документ для того, кто собирает установщик и выкладывает его людям.

## Что получается

`release/Astral-Setup-<версия>.exe` — обычный установщик NSIS:

- ставится **для текущего пользователя**, без запроса прав администратора;
- создаёт ярлык на рабочем столе и в меню «Пуск»;
- кладёт приложение в `%LOCALAPPDATA%\Programs\Astral` и корректно удаляется через
  «Установка и удаление программ»;
- все ядра (`xray.exe`, `sing-box.exe`, `wintun.dll`, `geoip.dat`, `geosite.dat`)
  уже внутри — первый запуск не требует интернета;
- данные и логи пишутся в `%APPDATA%\Astral` и не удаляются при обновлении или удалении.

Требования: Windows 10/11 x64. Режим TUN при каждом включении просит UAC
(так работает драйвер Wintun), режим PROXY — нет.

## Подписки и маршрутизация

Принимаются ссылки `vless://`, а также подписки, которые отдают:

- список `vless://` (в том числе в base64);
- полный конфиг Xray с `outbounds`, `dns` и `routing`;
- полный конфиг sing-box с `outbounds`, `dns` и `route`.

Правила маршрутизации из конфига сохраняются: обход локальных сетей и GeoIP/GeoSite,
блокировка рекламы, отдельные маршруты для доменов, портов и сетей, а также
балансировщики Xray. Если в sing-box выход описан группой `selector`/`urltest`,
берётся первый узел из её списка. Правила применяются автоматически, как в Incy:
отдельного переключателя нет. Списки `geoip.dat` и `geosite.dat` уже лежат рядом
с ядром, интернет для правил не нужен.

## Настройки

Вкладка **«Настройки»** в правом нижнем углу открывает панель снизу — с четырьмя
разделами:

- **Подключение** — порты SOCKS5/HTTP, имя TUN, MTU и DNS.
- **Маршрутизация** — блокировка рекламы (`geosite:category-ads-all`) и
  принудительный обход локальной сети. Правила подписки учитываются всегда.
  Изменения применяются после переподключения.
- **Подписки** — автоматическое обновление с периодом от 30 минут до суток и кнопка
  «Обновить все». Обновление работает и при включённом VPN: запрос идёт через
  локальный прокси Astral. Время последнего обновления видно рядом с переключателем.
- **Система** — автозапуск при входе в Windows (запись в `HKCU\...\Run`, без прав
  администратора). Доступен в установленной версии.

Настройки хранятся в `%APPDATA%\Astral` и не сбрасываются при обновлении или удалении.

## Сборка

```powershell
npm install
npm run fetch:cores   # один раз: скачивает Xray, sing-box, wintun в bin/
npm run dist
```

Готовый файл: `release/Astral-Setup-<версия>.exe` (~150 МБ).
Версия берётся из поля `version` в `package.json` — поднимайте её перед каждым релизом.

Проверка без установщика:

```powershell
npm run pack                     # release/win-unpacked/
.\release\win-unpacked\Astral.exe
```

Внутри собранного приложения:

```
Astral.exe
resources/
  app.asar          оболочка Electron
  dist/             интерфейс (Vite)
  server/           локальный движок
  bin/              ядра и лицензии
  icon.png
  THIRD-PARTY.md
  licenses/         тексты OFL для шрифтов
```

## Как это работает в собранном виде

1. `Astral.exe` запускает локальный движок (`resources/server/index.mjs`) отдельным
   процессом в режиме Node.
2. Движок слушает случайный свободный порт на `127.0.0.1` и отдаёт и интерфейс,
   и API (`/api/session`, `/api/import`, `/api/probe`).
3. Окно открывает этот локальный адрес. Наружу ничего не публикуется.
4. `runtime/` (конфиги, pid, бэкап системного прокси) живёт в `%APPDATA%\Astral\runtime`,
   поэтому установка в защищённую папку не ломает приложение.
5. При закрытии окна движок останавливается, системный прокси восстанавливается.

## Релиз через GitHub Actions

`.github/workflows/windows-installer.yml` собирает установщик на каждый тег `v*`
и прикрепляет `Astral-Setup-*.exe` к GitHub Release.

```powershell
# поднять версию в package.json, затем
git tag v1.0.0
git push origin master --tags
```

Ядра в репозиторий не коммитятся (папка `bin` в `.gitignore`) — workflow скачивает
их сам через `npm run fetch:cores`.

## Подпись кода — обязательный шаг перед массовой раздачей

Сейчас установщик **не подписан**. Windows покажет предупреждение SmartScreen
(«Неизвестный издатель»), а антивирусы могут ругаться на `xray.exe`/`sing-box.exe`.
Это главный барьер для доверия пользователей.

Варианты:

- **EV-сертификат** (USB-токен или облачный HSM) — даёт репутацию сразу.
- **Azure Trusted Signing** — дешевле, подпись через `signtool` в CI.

Как только сертификат есть, electron-builder подпишет всё автоматически:

```powershell
$env:CSC_LINK = "C:\path\to\cert.pfx"      # или base64 сертификата
$env:CSC_KEY_PASSWORD = "пароль"
npm run dist
```

В CI эти значения кладутся в секреты `CSC_LINK` и `CSC_KEY_PASSWORD`.

## Автообновление (следующий шаг)

`electron-builder` уже генерирует `latest.yml` и `app-update.yml` с репозиторием
`ressedich/astral`. Чтобы приложение обновлялось само, нужно добавить пакет
`electron-updater` и вызвать `autoUpdater.checkForUpdatesAndNotify()` в
`electron/main.cjs` после `ready`. Тогда новая версия будет скачиваться с GitHub
Releases и ставиться при перезапуске.

## Частые вопросы

**Порт занят.** Приложение выбирает свободный порт при старте, конфликтов быть не должно.
Если движок не поднялся, окно покажет ошибку, а лог лежит в
`%APPDATA%\Astral\logs\engine.log`.

**TUN не включается.** Нужны права администратора — подтвердите запрос UAC.
Если запрос отклонить, останется режим PROXY.

**Обновление поверх старой версии.** Достаточно запустить новый установщик.
Настройки и подписки сохраняются (`%APPDATA%\Astral`), старые процессы ядер
перезапускаются при старте.

**Удаление.** «Установка и удаление программ» → Astral. Данные в `%APPDATA%\Astral`
остаются; удалите вручную, если нужна полная очистка.
